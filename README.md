# J.A.R.V.I.S. — جارویس، پروژه مستقل از ماریا

**نسخه: 1.0.0 (Source + Windows build pipeline)** | **زبان: فارسی** | **اجرا: Windows 10/11 + Python 3.11+، یا EXE ساخته‌شده در Windows**

این پروژه مطابق شش پرامپت فایل فارسی «جارویس خودت رو بساز» به‌صورت مستقل طراحی شده است و هیچ وابستگی، شناسه نصب، فایل یا پوشه مشترکی با پروژه‌های MARIA ندارد.

## شروع سریع در ویندوز (بدون کامپایل)

1. ZIP پروژه را استخراج کن.
2. Python 3.11 یا جدیدتر نصب کن.
3. فایل `run_jarvis_windows.bat` را باز کن؛ یا در PowerShell اجرا کن:

   ```powershell
   cd path\to\Jarvis
   py -3 start_jarvis.py
   ```

4. مرورگر به‌صورت خودکار `http://127.0.0.1:8800` را باز می‌کند. برای پایان، پنجره ترمینال را ببند.
5. ۳۰ یادداشت فارسی نمونه آماده است. برای استفاده از یادداشت‌های خودت، در `config.json` مقدار `notes_folder` را با مسیر کامل پوشه Markdown جایگزین کن و برنامه را دوباره اجرا کن.

اگر می‌خواهی صدای طبیعی فارسی داشته باشی:

```powershell
py -3 -m pip install edge-tts
```

**توجه:** صدای آنلاین، متن پاسخ را برای تولید MP3 به سرویس خارجی می‌فرستد. برای قطع آن در `config.json` گزینه `online_tts` را `false` بگذار.

## اتصال مغز هوش مصنوعی

پیکربندی در `config.json` (فایل محلی که Git آن را نادیده می‌گیرد) انجام می‌شود. **هرگز API key را در چت یا GitHub منتشر نکن.**

| `provider` | پیش‌نیاز | توضیح |
|---|---|---|
| `codex-cli` (پیش‌فرض) | `npm install -g @openai/codex` و `codex login` | اتصال از طریق ابزار رسمی Codex پس از ورود به حساب. هزینه/سهمیه تابع حساب و محدودیت‌های ارائه‌دهنده است. |
| `claude-cli` | نصب Claude Code و ورود به حساب | پاسخ به روش `claude -p`، ابزارها خاموش هستند. |
| `openai-api` | کلید و اعتبار API | کلید را در config یا متغیر `OPENAI_API_KEY` نگه دار. API هزینه مصرف جدا دارد. |
| `anthropic-api` | کلید و اعتبار API | کلید یا متغیر `ANTHROPIC_API_KEY`. |
| `notes-only` | بدون مدل | فقط متن مرتبط از یادداشت‌ها نمایش می‌دهد. هوش مصنوعی مولد نیست. |

اگر provider در دسترس نباشد، جارویس **صادقانه به حالت خلاصه محلی** برمی‌گردد. این حالت برای استفاده از رابط و حافظه بدون ورود به سرویس هوش مصنوعی مفید است؛ کیفیت پاسخ مولد را جایگزین نمی‌کند.

## دقیقاً شش مرحله PDF

1. **کهکشان دانش:** `index_notes.py` تمام فایل‌های `.md` را تبدیل به `web/data.js` می‌کند؛ هر ستاره `id` عددی، عنوان، پوشه و خلاصه حداکثر ۶۰۰ نویسه دارد. پیوند از عنوان یا `[[wikilink]]` استخراج می‌شود. 3d-force-graph از CDN بارگیری می‌شود. حالت دوبعدی قابل‌کلیک هنگام نبود CDN/WebGL استفاده می‌شود.
2. **مغز متصل به منابع:** `POST /ask` سؤال را با حداکثر شش یادداشت مرتبط و شناسۀ منبع به مدل می‌دهد. نام منابع همراه پاسخ برمی‌گردد. گفت‌وگو تاریخچه کوتاه دارد. برای اطلاعات ناموجود ادعا نمی‌سازد.
3. **صدای فارسی:** `webkitSpeechRecognition` / `SpeechRecognition` با `fa-IR`، `speechSynthesis` با صدای فارسی در مرورگر و `POST /speak` با edge-tts و `fa-IR-FaridNeural` در صورت نیاز و فعال بودن صدای آنلاین.
4. **پرواز به منبع:** نمایش پنل سمت راست ستاره، حرکت دوربین؛ در پاسخ با چهار منبع یا بیشتر برجسته‌سازی گروهی انجام می‌شود.
5. **شخصیت:** لحن محترمانه، خونسرد و کوتاه و سلام متناسب با ساعت و شمارش واقعی یادداشت‌ها.
6. **حافظه:** `یادت باشه که...` یا دکمه افزودن یادداشت، `POST /remember`، ساخت فایل Markdown در `notes/inbox` و به‌روزرسانی لحظه‌ای نقشه.

موارد معرفی‌شده در صفحه ۹ PDF (Wake word «Hey Jarvis»، کنترل کامل سیستم ویندوز، هولوگرام دقیق GPU، کنترل دائمی پس‌زمینه و جستجوی زنده) **جزو شش پرامپت اصلی نیستند و در این نسخه پیاده‌سازی نشده‌اند**. آن‌ها امکانات یک محصول توسعه‌یافته‌تر در راهنما هستند، نه قابلیت‌های تضمین‌شده شش پرامپت.

## فایل نصب مستقل ویندوز

برای ساخت `Jarvis.exe` در **خود ویندوز**:

```powershell
./build_windows.ps1
```

- با PyInstaller خروجی `dist/Jarvis.exe` ساخته می‌شود.
- اگر NSIS نصب باشد، علاوه بر آن `dist/Jarvis-Setup-1.0.0.exe` ساخته می‌شود.
- مسیر نصب NSIS: `%LOCALAPPDATA%\Programs\Jarvis`؛ داده‌ها در `%LOCALAPPDATA%\Jarvis` نگهداری می‌شوند.
- `appId` یا مسیر MARIA به هیچ وجه استفاده نمی‌شود.
- Uninstall یادداشت‌های کاربر را حذف نمی‌کند.
- فایل `.github/workflows/windows-installer.yml` برای ساخت خودکار EXE با GitHub Actions ویندوزی آماده است؛ پس از انتشار در مخزن **مجزا** Jarvis قابل استفاده خواهد بود.

**این ZIP حاوی کد منبع و ابزار ساخت نصب‌کننده است، نه یک EXE از قبل کامپایل‌شده.** ساخت باینری Windows در محیط ویندوز یا GitHub Actions لازم است.

## بررسی و تست

```powershell
py -3 -m unittest discover -s tests -v
py -3 index_notes.py
py -3 server.py --open
```

تست‌ها ایندکس و پیوندها، بازیابی، ثبت حافظه، پایداری ID، محافظت از فایل‌های خصوصی، Origin/Host، محدودیت حجم ورودی و API را پوشش می‌دهند. آزمایش واقعی میکروفون، صدای فارسی، Codex/Claude و نصب EXE باید روی ویندوز مقصد انجام شود.

## امنیت و حریم خصوصی

- فقط روی `127.0.0.1` سرویس می‌دهد؛ نه روی اینترنت یا LAN.
- روت‌های استاتیک تنها فایل‌های مشخص `web/` را ارائه می‌دهند؛ `config.json` و پوشه یادداشت مستقیماً سرو نمی‌شوند.
- دستورات CLI با `shell=False` فراخوانی می‌شوند؛ Codex در حالت `read-only` اجرا می‌شود.
- تنها اقدام نوشتنی رابط، ایجاد یادداشت جدید در `inbox/` و نوسازی شاخص است.
- مدل نباید متن یادداشت را به‌عنوان فرمان اجرا کند؛ با این حال اتصال به سرویس آنلاین متن یادداشت‌های منتخب را به سرویس آن مدل منتقل می‌کند.
- جایگزینی پوشه یادداشت‌های نمونه با یادداشت‌های واقعی نیازمند تصمیم آگاهانه درباره ارسال داده به مدل است.

## ساختار پروژه

`jarvis_core.py` داده، بازیابی، مدل، حافظه؛ `server.py` HTTP و صدا؛ `index_notes.py` فهرست‌سازی استاندارد؛ `web/` رابط؛ `notes/` سی یادداشت نمونه؛ `tests/` آزمون؛ `packaging/` NSIS؛ `start_jarvis.py` راه‌انداز مستقل؛ `build_windows.ps1` ساخت EXE؛ `assets/` آیکون اختصاصی.


## نسخه سینمایی / Premium Command Center (2026-10-20)

نسخه جدید با رابط HDR-like مشکی/آبی، هولوگرام SVG/Particle، HUD وضعیت‌های زنده، فیلتر دسته‌بندی، نمایش خوشه‌ای منابع و مرکز فرماندهی مجزا ارائه شده است. تصویر سه‌بعدی ابتدا از کتابخانه PDF یعنی `3d-force-graph` استفاده می‌کند؛ اگر CDN در دسترس نباشد، یک رندرکننده مستقل WebGL سه‌بعدی دارد و در نهایت برای محیط‌های فاقد WebGL به دوبعدی باز می‌گردد. رابط به صورت RTL واکنش‌گرا طراحی شده و به سادگی فقط صفحه نمایشی نیست.

### قابلیت‌های پیشرفته معرفی‌شده در آخر PDF

| بخش | پیاده‌سازی و محدودیت |
| --- | --- |
| هولوگرام ذره‌ای و HUD | SVG + Canvas ذره‌ای، وضعیت listening/thinking/speaking/success، موج منبع. نسبت دادن به صدای خروجی با وضعیت TTS مرورگر؛ در حالت آفلاین با وقایع UI کار می‌کند. |
| Hey Jarvis | اختیاری با SpeechRecognition مداوم **تا وقتی صفحه باز و قابل استفاده باشد**. بیدارباش دائمی پس‌زمینه ویندوز هنوز پیاده‌سازی نشده است. |
| Whisper فارسی محلی | زیرساخت `/api/transcribe` و ضبط WebM، با `faster-whisper` و مدل از پیش موجود. **نصب مدل، صحت GPU/CUDA و ساخت موتور آفلاین در فایل EXE هنوز در محیط ویندوز تأیید نشده است**. |
| صدای طبیعی فارسی | `speechSynthesis` مرورگر یا `edge-tts` با تنظیم صدای فارسی. شبکه برای edge-tts لازم است. |

### اتصال مدل Whisper محلی

در Python معمولی (نه فایل EXE بسته‌بندی‌شده):

```powershell
py -3 -m pip install faster-whisper
```

یک مدل faster-whisper سازگار را **خودت از منبع معتبر** دانلود و در پوشه محلی قرار بده، سپس مسیر پوشه مدل (`model.bin` داخل آن) را در `config.json` به صورت `offline_stt_model` وارد کن. تنظیم `offline_stt_device` می‌تواند `auto`, `cpu` یا `cuda` باشد. مسیر مدل قبل از استفاده بررسی می‌شود؛ هیچ دانلود پنهانی صورت نمی‌گیرد. میکروفون مرورگر همچنان به عنوان جایگزین باقی می‌ماند.

### فرمان‌های واقعی پشتیبانی‌شده

- «باز کن نوت پد»؛ «ماشین حساب رو باز کن»
- «سرچ کن گوگل آب و هوای تهران»؛ «جستجو کن یوتیوب آموزش پایتون»
- «صدا رو زیاد کن»؛ «صدا رو کم کن»؛ «بی صدا کن»
- «تایمر ۵ دقیقه»
- «سیستم رو قفل کن» ← تأیید دوباره لازم دارد.

با کلید Ctrl+K به خط فرمان برو. ابزارهای سیستم را از «مرکز فرماندهی» اجرا کن. برای واژه بیدارباش «Hey Jarvis»، ابتدا میکروفون مرورگر را اجازه بده، سپس در مرکز فرماندهی آن را روشن کن. پس از بیدارباش، فقط فرمان‌های به‌صورت قطعی شناخته‌شده اجرا می‌شوند؛ بقیه به مکالمه از یادداشت‌های شخصی می‌روند.

### آزمون‌های افزوده

`python -m unittest discover -s tests -v` اکنون علاوه بر هسته، برنامه‌ریز دستور صوتی، ممانعت از اجرای فرمان دلخواه، درخواست‌های دارای Origin، تأیید قفل ویندوز، محدودیت Whisper و API ابزارها را هم می‌آزماید.

### GitHub Actions

مخزن **کاملاً مستقل** `amirgzva-d/Jarvis` پس از آپلود فایل‌ها، در هر push روی main روی Windows runner تست و بسته‌بندی می‌شود. قدم ساخت شامل نصب PyInstaller و NSIS است. برای دریافت Setup.exe، وارد تب Actions → Build Jarvis Windows installer → آخرین Run → Artifacts شو. وضعیت موفقیت Build را در خود GitHub بررسی کن؛ خروجی تست ویندوز واقعی را تا پیش از پایان Workflow تأییدشده فرض نکن.
